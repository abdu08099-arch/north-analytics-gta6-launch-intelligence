## Update, same week: first connector (GDELT)

Started early because GDELT only keeps about 3 months of searchable coverage, and launch week is now.

- `GdeltConnector`: 1 timeline request + 4 article-list requests per run, 6 seconds apart, bounded retries, non-JSON responses rejected.
- Runner change: payloads are stored as they arrive; a run that fails halfway is `partial` and keeps what it got.
- The runner now refuses sources marked blocked, deferred, conditional or disabled, even if code exists.
- Method note: `docs/methodology/gdelt-news-coverage.md`.

### Tests run (actual results)
- `uv run pytest`: **34 passed** on SQLite and on PostgreSQL 16.15.
- **Live run from the cloud workspace: failed.** GDELT answered HTTP 429 to almost every request from that shared IP. In the first live attempt the timeline request succeeded on its third try, then the article lists failed. That attempt led to the `partial` change above. Earlier, a single manual article-list request returned HTTP 200 with real metadata. **A full successful run has not been verified yet.** It must be run from a personal machine.
